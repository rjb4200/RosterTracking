# completion-certificates Specification

## Purpose
Produce the per-participant course-completion certificate that KBEMS requires as proof of completion for a continuing-education class, from the same immutable revision facts used for official rosters.
## Requirements
### Requirement: Certificates are generated from finalized revision facts
The system SHALL generate a completion certificate only from a finalized roster revision and SHALL use that revision's participant, class, instructor, and course facts rather than mutable current records.

#### Scenario: Generate a certificate
- **WHEN** authorized staff generate a certificate for a finalized revision
- **THEN** the certificate contains the participant, class, instructor, and course facts preserved by that revision

#### Scenario: Block a non-finalized source
- **WHEN** staff attempt to generate a certificate for a class without a finalized revision
- **THEN** the system rejects the request without returning a certificate

### Requirement: One certificate per participant
The system SHALL produce a separate certificate for each active participant of the finalized revision, addressed to that participant.

#### Scenario: Generate for every participant
- **WHEN** a finalized revision has several active participants and staff request certificates
- **THEN** the system produces one certificate per participant with that participant's name

#### Scenario: Exclude removed attendance
- **WHEN** a participant's attendance was removed before finalization
- **THEN** no certificate is produced for that participant

### Requirement: Certificate content
Each certificate SHALL show the participant name, the class hours, the course type, the course number, the course-completion date, and the instructor name, and SHALL render the instructor title and the class name on the signature line. The certificate SHALL leave the instructor signature blank for physical signing.

#### Scenario: Populate certificate fields
- **WHEN** a certificate is generated
- **THEN** the participant name, class hours, course type, course number, completion date, and instructor name are populated

#### Scenario: Omit a missing optional value
- **WHEN** the class has no course number
- **THEN** the certificate leaves that field blank rather than printing a placeholder

#### Scenario: Leave the signature blank
- **WHEN** a certificate is generated
- **THEN** the instructor signature field is blank

### Requirement: Certificate generation is controlled and audited
The system SHALL allow an assigned instructor to generate certificates only for a finalized class to which they are assigned, and Training Majors and Administrators to generate them for any finalized class. The system SHALL record the actor, the revision, the participant, and that the signature field was left blank for each generation, and SHALL not retain generated certificate bytes.

#### Scenario: Permit an assigned instructor
- **WHEN** an instructor generates certificates for a finalized class to which they are assigned
- **THEN** the system permits the request

#### Scenario: Deny an unrelated instructor
- **WHEN** an instructor generates certificates for a finalized class to which they are not assigned
- **THEN** the system denies access without disclosing certificate content

#### Scenario: Record the blank signature
- **WHEN** a certificate is generated
- **THEN** the system records an audit event noting the actor, the participant, and that the signature was left blank

#### Scenario: Do not retain generated bytes
- **WHEN** the same certificate is requested again
- **THEN** the system regenerates it from the revision without retaining the earlier copy
